# P26 — Conversation, LLM, Memory & Promenade Depth (v1.5)

> **Status: 🚧 fleshed / in progress.** Track: v1.5. Source: [MASTER.md §11.2-G/H](../MASTER.md#112-v15--deferred-backlog-aggregated-deduped).
> Deepens the conversation subsystem (routing, tools, memory, streaming, NPC initiative) and the Hyde Park promenade. The determinism boundary is unchanged: the LLM layer never advances the gameplay PRNG; trigger rolls for NPC-initiated conversations are gameplay-PRNG draws and the LLM authors text only.

## Depends on
P4 (ballroom/LLM round-trip), P12 (promenade), P17 (semantic memory), P18 (flavor). All ✅ done.

## Goal
Conversation gets smarter (cross-house memory, key-moment routing, richer tools, streaming, NPC initiative) and the promenade gains the tactical depth deferred at P12.

## Resolved decisions (user-elected 2026-07-17 + adopted defaults)

1. **Q14 (NPC-initiated) — BOTH shapes.** (a) *Ballroom approach*: deterministic roll on `enterBallroom` picks whether/which NPC approaches first; LLM authors the opener as the first history exchange; opener failure degrades silently to a normal ballroom. (b) *Calling-card tick phase*: deterministic per-tick roll mints a persisted `CallingCard`; accepting opens a 1-on-1 **Visit** session (promenade machinery, no location gate — the caller comes to you); decline/expiry are RNG-free.
2. **Q15 (streaming) — two-phase calls.** Call #1 streams dialogue prose over SSE (`generateContentStream`, partial-token render, mid-stream cancel). Call #2 is a non-streaming forced-function-call **classify** (tactic/multiplier/moodHint/toolCalls; always Flash). Combat + history append stay atomic AFTER both calls. Any pre-commit failure on the streamed path falls back ONCE to the existing single-shot `/api/llm/conversation`; timeout does NOT retry (15s total budget preserved). Flavor prose also streams.
3. **Embedding provider — seam only.** Provider abstraction server-side (`EMBED_PROVIDER` env, Gemini the only live provider; no new API key). The **re-embed-from-sourceText** path ships and replaces silent discard-on-mismatch.
4. **Multi-character scenes — scene-via-contents.** The "Other characters in this scene" section moves OUT of the cached persona `systemInstruction` INTO per-turn `contents` (P12/P17 "fast-changing state rides contents" precedent). No cache fragmentation; `PERSONA_CACHE_VERSION` `"v4"` → `"v5"`. Promenade becomes multi-partner (up to 3, deterministic draws; player picks the per-message target). P25's rival personas reuse this infra without a second re-key.
5. **Skeleton correction:** `ComplimentMount` is ALREADY the 5th `TACTICS` entry (P12). Making it a ballroom tactic extends the 3 synergy maps + the ballroom UI + a mount-gate override in `resolveCombat`; the `TACTICS.length !== 5` guard does **NOT** bump (no 6th tactic ships).
6. **Adopted without asking** (mechanical, sanctioned by the skeleton): key-moment enum wires all four spec moments but `"audience"` is never emitted at P26 (no audience conversation mode exists — stays "pre-wired as plumbing"); cross-house retrieval semantics per G4 below; stance's ONLY promenade effect is the Mingle mount-bonus gate (no Wallflower/TargetedPursuit multipliers in promenade — spec §3 L444-450 math is `(base + bonus) × quality` only); flavor authoring/regenerate supersede the P18 "produced at most once" pin to "at most once per player election".

## In scope — G track (LLM, routing & memory)

### G1. Two-phase streaming dialogue + streaming flavor (Q15)
- **`server/index.ts`**: two new exact-match POST routes — `/api/llm/conversation/stream`, `/api/llm/flavor/stream` (and `/api/llm/classify`, `/api/llm/opener` from G2/G6). SSE responses (`content-type: text/event-stream`) cannot reuse `respondJson`; each handler owns its writer. Per-route try/catch: on mid-stream error emit an SSE `error` event then `res.end()` (the `if (!res.headersSent)` 500 fallback only covers pre-stream failures).
- **`server/conversationStream.ts`** (new): `handleConversationStream` — parses `ProxyConversationRequestSchema` (422 pre-stream), resolves the persona cache + `buildContents` EXACTLY as `handleConversation`, then `ai.models.generateContentStream({model, contents, config:{...cachingConfig, maxOutputTokens: LLM_OUTPUT_TOKEN_BUDGET, thinkingConfig:{thinkingBudget:0}, abortSignal}})` — **no tools/toolConfig** (prose-only; the P18 thinking-off + prompt-steered-length precedent applies). Emits `data: {"kind":"delta","text":...}` per chunk, terminal `data: {"kind":"done","dialogue":<full>}`, or `data: {"kind":"error","reason":"timeout"|"network"|"internal"}`. 13s composite budget. Error-mapper helpers are copied per-file (the deliberate-triplication precedent).
- **`server/classify.ts`** (new): `handleClassify` — input `ClassifyRequestSchema` (new, `src/llm/types.ts`): `{ freeformMessage, dialogue, targetCharacterId, sceneCharacters: [{id,name}], mode }`. Forced function call `CLASSIFY_TOOL` (new in `server/tools.ts`: same fields as `RESPOND_TOOL` minus `dialogue`; `allowedFunctionNames: ["classify"]`), always `MODEL_DEFAULT`, no persona cache, plain systemInstruction (small static classifier instruction). Validates `ClassifyResponseSchema` (= `ConversationResponseSchema` minus `dialogue`) → 200/422/408/502/500.
- **`src/llm/client.ts`**: `sendStream(request, signal, onDelta): Promise<string>` — fetch + `body.getReader()` SSE line parser; returns the full dialogue; throws the existing typed errors. `classify(request, signal): Promise<ClassifyResponseRaw>`.
- **`src/runtime/conversationOrchestrator.ts`**: `sendStreamed(request, pinnedIntent, onDelta): Promise<ConversationOutcome>` — stream → classify → compose `{dialogue, ...classify}` → `narrowResponse`. Single 15s budget spans both calls (one timeout controller). On `NetworkError`/`SchemaError` from either call (NOT timeout, NOT user-cancel): one fallback attempt via the existing `send()`. `requestId` staleness + `AbortSignal.any` composition unchanged; `abortCurrent()` cancels mid-stream.
- **Store**: `sendBallroomMessage`/`sendPromenadeMessage` (+G2's `sendVisitMessage`) accept optional `onDelta?: (text: string) => void` in their input and route through `sendStreamed` when provided, `send` otherwise. Post-await mutation/commit logic byte-identical — partial tokens are UI-ephemeral only; a failed exchange still appends nothing and advances nothing.
- **UI**: `BallroomView`/`PromenadeView`/`VisitView` hold a `streamingText` local state fed by `onDelta`; render progressively in the dialogue area ("..." until first delta; cleared on resolve/fail).
- **Flavor streaming**: `server/flavorStream.ts` (new) — `handleFlavorStream`, same prompt via `buildFlavorPrompt`, `generateContentStream`, same SSE event shape. `src/llm/flavor.ts` gains `fetchFlavorTextStream(context, signal, onDelta)`. `flavorOrchestrator.generate` uses the stream path with a module-level transient buffer `Map<FlavorContentId, string>` + `subscribeStreaming(cb)`/`streamingTextFor(id)` (consumed via `useSyncExternalStore` in the expanders); falls back to single-shot `fetchFlavorText` on stream failure; **persists only the final full text** via `recordFlavorText` (stubs still never persist; buffer cleared on settle).

### G2. NPC-initiated conversations (Q14 — both shapes)
- **New entity + state field (quint-sync)**: `CallingCardId` brand in `rng.ts` (+ `CallingCardIdSchema`, + `rng.seeds.ts` type re-export). `CallingCardSchema` in `entities.ts`: `{ id, callerCharacterId, issuedAtTick, expiresAtTick (ABSOLUTE end-tick), status: "Pending"|"Accepted"|"Declined"|"Expired" }`. `GameState.callingCards: z.map(...)` — never-delete, status flips only. Full quad+1 sync: `GameStateSchema` + `hashableState` (`serializeRegistry`) + `selectGameState` + `overwriteFromGameState` + `createInitialState`; SaveV1 array-of-tuples emit/lift (in-place edit, NO save-version bump per the pre-release posture). `makeCallingCardId` = draw-free state-walk factory in `src/game/fixtures/callingCardIdFactory.ts` (`card-<i>`, index = `state.callingCards.size` — cards are never deleted so size is monotonic).
- **New tick phase** `applyCallingCardPhase` (`src/game/rules/callingCards.ts`): PHASES 16 → **17**, inserted immediately after `applyGlobalEventPhase` (before rivals; "rivals last among RNG-consuming phases" holds). Order inside: (1) RNG-free expiry sweep — `status === "Pending" && tick >= expiresAtTick` → `"Expired"`; (2) **unconditional 1 player-rng draw** (P13 burn-on-all-outcomes precedent) vs `CALLING_CARD_PROBABILITY_BASIS_POINTS`; outcome DISCARDED when a Pending card already exists (max 1 Pending) or the pool is empty; (3) on live hit, 1 more draw picks the caller from the lex-sorted alive non-player non-rival pool (same predicate as `eligiblePromenadePartners`), mints `{status:"Pending", expiresAtTick: tick + CALLING_CARD_EXPIRY_TICKS}`.
- **Store actions**: `acceptCallingCard(cardId)` — modal gates at top (`PlayerExiled`/`ElopementInProgress` via `hasActivePlayerElopement`), rejections `CardNotPending` | `CallerDead` | `SessionAlreadyOpen`; flips status → `"Accepted"`, opens a **Visit** session, fires the opener round-trip (below), direct-publishes `CallingCardAccepted`. `declineCallingCard(cardId)` — same gates; status → `"Declined"`, flat `CALLING_CARD_DECLINE_AFFECTION_PENALTY` applied to the pair's affection (clamped at the mutation site), direct-publishes `CallingCardDeclined`. No RNG in either.
- **Visit session**: `VisitSessionId` brand + `makeVisitSessionId(tick)` (`visit-<tick>`) in `rng.ts`. Orchestrator `SessionState` gains `{ mode: "Visit"; sessionId; tickAtEntry; callerCharacterId; callingCardId }` + `beginVisitSession` (mode-conflict throws, same-tick idempotence) — every `currentMode()` consumer and both cross-mode `SessionAlreadyOpen` gates widen. Wire `mode` enum widens to `"Visit"` (`.default("Ballroom")` keeps compat) + `VISIT_MODE_FRAMING_PREFIX` in `buildContents` (drawing-room call framing; rides contents, never systemInstruction). `sendVisitMessage`/`exitVisit` mirror `sendPromenadeMessage`/`exitPromenade`: promenade tactic set + `resolvePromenadeCombat` + `appendPromenadeExchange`; **post-await exile/elopement short-circuits from birth** (H5 shape); `exitVisit` = commit-on-leave `advanceTickPure` + the full publisher fan-out. `VisitView` (`src/ui/visit/`) is a thin sibling of `PromenadeView` (shared `PromenadeTacticButtons`; no premature shared abstraction). `App.tsx` view routing: Elopement > Visit > Promenade > ...
- **Ballroom approach**: in `enterBallroom`, ONLY when `beginSession` creates a NEW session (skip on same-tick idempotent re-entry): 1 player-rng draw vs `BALLROOM_APPROACH_PROBABILITY_BASIS_POINTS`; on hit, 1 draw picks the approacher from the ballroom roster; the entry result + `BallroomEntered` event carry `approachingCharacterId: CharacterId | null`; UI pre-selects the approacher.
- **Opener round-trip** (shared by both shapes): `server/opener.ts` (new) — `POST /api/llm/opener`, input `OpenerRequestSchema` `{ characterStateSnapshot, history, mode, approachContext: "Ballroom"|"Visit" }`; reuses `getOrCreatePersonaCache` + a contents-borne "[You approach the player first — open the conversation]" framing; plain prose (`thinkingBudget: 0`), returns `{ text }`. Client `fetchOpener` (timer-free); store fires it post-entry/accept with a 10s `OPENER_TIMEOUT_MS` signal, appends via new free store action `recordNpcOpener(targetCharacterId, text)` (appends `{speaker:"other", classifiedTactic:null}` to `conversationHistory`, no tick, no publishers — interactive-only LLM append, same class as normal exchanges). Failure → silent degrade (no opener).
- **Events**: `conversationBus` gains `CallingCardIssued`/`CallingCardExpired` (diff-published) + `CallingCardAccepted`/`CallingCardDeclined` (wrapper direct-published) + `VisitEntered`/`VisitExited`; `BallroomEntered` payload widens. New diff helper `publishCallingCardTransitions(before, after)` rides every tick-advancing wrapper EXCEPT `runYearPass` (year-pass STEPS has no calling-card phase) → **publisher set becomes 14/14/11** (supersedes P23 13/13/11); `exitVisit` joins the 14-group.
- **Notification surface**: Pending card chip reusing the P21 notification row ("Lady X has left her card"), with accept/decline affordances.

### G3. Key-moment Pro routing
- `ProxyConversationRequestSchema` + `OpenerRequestSchema` gain `keyMoment: z.enum(["proposal","scheme","duel","audience"]).nullable().default(null)`. `routeModel(history, keyMoment)` (`server/routing.ts`): `keyMoment !== null || history.length === 0` → `MODEL_FIRST_MEETING`, else `MODEL_DEFAULT`. Classify stays Flash always.
- Client-side pure helper `computeKeyMoment(state, targetCharacterId): KeyMoment | null` (`src/game/rules/keyMoments.ts`, pure, RNG-free): `"proposal"` when affection ≥ `AFFECTION_PROPOSAL_THRESHOLD` AND the target passes `isAvailableForRemarriage`-style availability (mirror the propose-gate readout inputs, RAW reputation per the P20 trip-hazard); `"duel"` when an unresolved grievance links the player house and the target's house (either direction); `"scheme"` when any Active player-house scheme has `targetCharacterId === target`. - Threaded from all three send sites (ballroom/promenade/visit).

### G4. Cross-house semantic retrieval
- **Write path** (`src/runtime/semanticIndex.ts`): subscribers drop their player-only early-returns and stamp real houses — `WhisperCreated` indexes ALL whispers (`houseId: event.destinationHouseId`); `SchemeCompleted` indexes ALL completions (`houseId: event.ownerHouseId`); `GrievanceRecorded` indexes all (`houseId: perpetratorHouseId`); `ArchetypeReclassified[Succession]` indexes ALL houses' successions (`houseId: character.houseId`). `ConversationResolved` unchanged (pairs are player-anchored by construction). Flag-guard-first + `index()` try/catch funnel preserved on every touched subscriber.
- **Retrieval filter** (`retrieve`): relaxes from `(houseId∈{null,PLAYER}) && (npcId∈{null,target})` to `e.houseId === null || e.houseId === PLAYER_HOUSE_ID || e.npcId === npcId` — the NPC's knowledge widens to events about THEMSELVES from any house, plus the player-perspective corpus + lore. Top-K/threshold/sort/degrade-to-`[]` unchanged. (Rationale: `semanticContext` feeds the NPC's reply, not the player's ledger — an NPC knowing gossip about themselves is in-fiction.)
- Entry ids, `evictByTick`, the 500-cap, and the Dexie schema are untouched (no `.version(3)`).
