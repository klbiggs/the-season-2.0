> **Status: ✅ done (closed 2026-07-17; all gates green incl. 30-run replay determinism + promotion determinism).** Track: v1.5.
> **Close-out (2026-07-17):** audit added coverage for the I3 BribeDriver fallback branch, the I2 archetype-via-classifyArchetype assertion, and the hire/fire/promote wrapper modal gates. Source: [MASTER.md §11.2-I](../MASTER.md#112-v15--deferred-backlog-aggregated-deduped). Split from the converged combined P24 (Stage I of three: P24a schemes/elopement · P24b artifacts · P24c staff).
> Turns the static 4-staff roster into a managed network: hire (procedural identity), fire, promote-to-character, location-specialized BribeDriver, and dynasty-perk bribery resistance.

## Depends on
P6 (staff subsystem — `StaffMember` / `state.staff` / `applyStaffOutputsPhase` / `tryAssignStaff` / `BASELINE_STAFF`), P15 (dynasty perks — the Whispers perk's "resistance to rival espionage" half), P23 (`applyLifespanModifiers` for promote-to-character lifespan; the maturation role rules). Independent of P24a/P24b.

## Goal
The downstairs network becomes a roster the player invests in: hire new staff (procedurally identified), fire them, promote a staffer into a marriage-eligible family Character, specialize the carriage-driver's intelligence by location, and harden against rival bribery via the Whispers dynasty perk.

## Locked design decisions (carried from combined-P24 convergence)
1. **Promote-staff-to-character = INCLUDED.** A `StaffMember` is promoted into a first-class player-house `Character` (new id, derived traits, mood, lifespan-rolled `deathAge`, marriage-eligible). (User-selected.)
2. **Never-delete invariant extends to staff.** Staff are never removed from `state.staff`; fire sets `dismissedAtTick`, promote sets `promotedToCharacterId`. Dismissed/promoted staff are inert (skipped in loyalty drift, bribery roll, cadence outputs, the roster active count). Matches the characters/houses/marriages/schemes/whispers never-delete pins.
3. **Promote gender is DRAWN, not derived.** `StaffMember` has no gender field; `promoteStaffToCharacter` draws gender on the player-house RNG stream (P16 precedent), NOT via `hashCharIdToGender` (P7 pin: fixed-fixture-only).

## In scope

### I1. Hire-staff (`makeStaffId`) + fire-staff
- **Today:** 4 baseline staff (`BASELINE_STAFF`, `fixtures/staff.ts:24-49`), all player-owned, ids are compile-time constants; **no `makeStaffId`, no hire/fire/dismiss anywhere** (grep-confirmed zero results; P15 did NOT ship fire). `StaffMember` (`entities.ts:404-420`).
- **New `makeStaffId(state)`** factory in `fixtures/staff.ts` (walks `state.staff` for the next index; draw-free) — the P6 plan reserved this for "P15+"; P24c ships it.
- **`StaffMember` gains** `dismissedAtTick: z.number().int().nonnegative().nullable()` (`.default(null)`) + `promotedToCharacterId: CharacterIdSchema.nullable()` (`.default(null)`). Edit the live schema in place.
- **`hireStaff()` free action** (or 1-tick — decide at convergence; default free): spend `STAFF_HIRE_WEALTH_COST`, create a procedurally-identified staff member (I4) via `makeStaffId`, `assignment: "None"`. Gates: modal-state, wealth, a roster cap (`STAFF_ROSTER_MAX` active). Direct-publishes `StaffHired`.
- **`fireStaff(staffId)` free action:** set `dismissedAtTick = state.tick`; the member stays in `state.staff` (never deleted) but is **inert** — `applyStaffOutputsPhase` (`staff.ts:76-139`) skips dismissed members in loyalty drift, bribery roll, and cadence output; the roster active-count and bribery-risk exclude them. Direct-publishes `StaffDismissed`. Firing a `BribedByRival` member is **allowed** — it's the only way to remove a turned member (matches the P6 note "the staff member must be FIRED to remove them").

### I2. Promote-staff-to-character (INCLUDED)
- **New pure rule `promoteStaffToCharacter`** (`src/game/rules/staffPromotion.ts`): convert a `StaffMember` → a first-class player-house `Character`. **Gender source (resolved — `StaffMember` has NO gender field, only `name`):** **DRAW** a gender on the player-house RNG stream (P16 procedural-NPC precedent) — NOT `hashCharIdToGender` (P7 pin restricts that hash to fixed fixtures; a promoted staffer is a new entity). The gender draw is the FIRST draw of the promotion budget so the subsequent role + `applyLifespanModifiers` reads are consistent. New `CharacterId` (`makeCharacterId`/existing factory); derive traits (`isGreedy` → `["Greedy"]` + a small generated pool, I4); role by gender (`Female → Spinster`, `Male → Dependent`/`Bohemian` per the maturation role rules); `mood: "Receptive"`; `age` rolled or a default adult age; `deathAge` via the P23 `applyLifespanModifiers` (gender + traits); `marriageId: null` (marriage-eligible); `archetype` via `classifyArchetype`. Mark the source staff `promotedToCharacterId = newCharId` (inert thereafter). **Promotion draw budget (player-house stream): gender → age → deathAge-base → traits**; the fresh-state hash shifts and is absorbed by the self-referential replay baseline. The new Character participates in all family/marriage/conversation systems immediately.
- **`promoteStaff(staffId)` action** (1-tick or free — default free): gates modal-state + roster + the staff is active (not dismissed/already-promoted). Direct-publishes `StaffPromoted`. Surfaces in `StaffPanel.tsx`.
- This is the heaviest item; it makes the spec's `staff` Character role (spec L540 enumerates `staff` as a role) reachable.
- **Converged build notes (folded from review — the `StaffMember`→`Character` line compresses four load-bearing edits):**

  2. **Role helper is module-PRIVATE:** `computeMaturationRole` (`maturation.ts:25`) is not exported — RE-IMPLEMENT the role logic inline in `staffPromotion.ts` (don't import).   4. **Full construction literal:** `CharacterSchema` (`entities.ts:210-267`) has ~24 required fields (25 with I3's new `assignedLocationId`). Don't omit: `birthTick, composure, maxComposure, happiness, temptationHookUnlocked, assignedTutorCharacterId, tutorBonusTraitGranted, dullSpouseExposureStartTick, parentCharacterIds, moodLockUntilTick, diedAtTick, equippedArtifactIds` (note: `equippedArtifactIds`, not `equippedArtifacts`), and `assignedLocationId`. `classifyArchetype` (`archetypes.ts:26`) is EXPORTED and reusable.

### I3. BribeDriver subject-selection specialization (spec §3 L457)
- **Today:** Snoop and BribeDriver pick the **identical** subject — lex-smallest living non-player NPC (`pickStaffWhisperSubject`, `staff.ts:161-219`); they differ only in cadence (Snoop 8, BribeDriver 12). Spec L457 wants the carriage driver to generate "whispers about characters whose recent travel matches" — a location-aware pick the P6 plan deferred for lack of NPC location tracking.
- **New minimal NPC location model:** add `assignedLocationId: LocationId` to `Character` (`.default("Capital")`; edit live schema in place). **Named `assignedLocationId`, NOT `currentLocationId`** — to avoid confusion with the existing `House.currentLocation` (`entities.ts:157`, the player-side comparison field that already exists; only the NPC-*side* per-character location is net-new). Society/rival NPCs get hash-derived stable locations per `CharacterId` (no per-tick churn, to bound the surface; a society-movement micro-step is a later option). **BribeDriver subject** = lex-smallest living non-player NPC whose `assignedLocationId === playerHouse.currentLocation` (the player's recent travel destination); fallback to the lex-smallest living non-player NPC when none match. Snoop keeps the location-agnostic lex-smallest pick. This finally differentiates the two assignments by *subject set*, not just cadence. (If the persisted per-Character slot proves unjustified at implementation, derive NPC locations on read instead.)
- **Converged build notes (folded from review):**
  1. **The new REQUIRED `Character.assignedLocationId` breaks every in-memory Character builder** — Zod `.default()` backfills only on `.parse()`, NOT object literals. Add the field to ALL builders (Files list undercounts — names only entities.ts+schema.ts): `npcs.ts:104`, `proceduralNpcs.ts:136`, `rivals.ts:210`, `conception.ts:199`, `proceduralProfiles.ts:118`, `bootstrap.ts:121` (player head), `factories.ts:107` (test). **Determinism:** set it draw-free in the bootstrap builders (constant, or `fnv1a32`-derived — no RNG draw), so no fresh-state draw is added; BUT the fresh-state HASH still SHIFTS (new projected non-uniform field) — restate the shift for the bootstrap path (the body acknowledges it only for the promote path).
  2. **Picker edit is a case-split, not just a pick tweak:** Snoop + BribeDriver currently SHARE one switch arm (`case "Snoop": case "BribeDriver":`, `staff.ts:165-179`) and both call `pickStaffWhisperSubject(acc)` (which takes only `state`). De-merge the case, give the picker a `location?: LocationId` param (or add a sibling `pickBribeDriverSubject`), and thread `playerHouse.currentLocation` only on the BribeDriver path.
  3. **Hash domain + helper:** use `fnv1a32` (`fixtures/hashCharIdToGender.ts:32`) — NOT `hashCharIdToGender` (P7-restricted). Hash the NPC `assignedLocationId` ONLY over the player-occupiable locations `{Capital, Country}` — of the 7 `LOCATIONS`, the other 5 (FinishingCapitalCultured/Political, CanalCity, RenaissanceCity, ForeignCapital) can never equal `playerHouse.currentLocation`, so hashing across all 7 would silently collapse BribeDriver back to the lex-smallest fallback.

### I4. Dynasty-perk loyalty effects + procedural staff identity
- **Dynasty-perk loyalty (spec L252 "whispers perk … resistance to rival espionage"):** the existing **Whispers** dynasty perk (P15, `dynastyLegacies.ts`) gains a staff effect — when the player house holds the Whispers perk, multiply the per-tick bribery probability (`STAFF_BRIBERY_PROBABILITY_BASE` = 0.05, `staff.ts:101-119`) by `WHISPERS_PERK_BRIBERY_RESISTANCE_MULTIPLIER` (< 1). Read the perk via the existing `hasDynastyPerk(state, "Whispers")`. No new perk; this wires the "resistance to rival espionage" half of the spec's Whispers perk that P15 left unwired. **Determinism note:** the multiplier changes the bribery-roll *threshold*, NOT the draw count — the per-tick bribery draw still fires for every Greedy sub-threshold staff regardless of the perk, so the RNG stream is undisturbed (only the comparison constant shifts).
- **Procedural staff identity:** hired staff (I1) get procedurally-generated identity from a transient/per-house draw — a staff name bank (`fixtures/staff.ts` or `nameBanks.ts`), `isGreedy` roll, `upkeepPerTick` range, starting `loyalty` range. Baseline staff stay the fixed `BASELINE_STAFF` four. `buildProceduralStaffMember(id, rngState)` mirrors `buildBaselineStaffMember` (`fixtures/staff.ts:51-63`) field-for-field.
