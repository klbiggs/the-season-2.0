## Depends on
P5 (schemes / `tryStartScheme` / scheme-resolution phase), P8 (rivals — for the rival-action pool widening + `RIVAL_ACTION_KINDS` guard), P9 (elopement singleton + modal-state gate), P23 (`mintMarriage` helper, `isSocietyHouse`, the re-widow role/archetype recompute), P15 (dynasty perks — Seduction perk interplay in C1).

## Goal
Seduction discovery becomes a legible multi-tick suspicion ramp the player can watch and abort; the player picks *which* family member runs a scheme; marriages can be deliberately dissolved (Abandonment) to free a remarriage; and elopement becomes a first-class subsystem (`state.elopements` Map) where the player runs interactive sprints and rivals/society run their own auto-resolving chases.

## Locked design decisions (carried from combined-P24 convergence)
1. **Elopement = FULL multi-character build.** `state.elopement` (singleton) → `state.elopements: Map<ElopementId, ElopementSprintState>`. Player runs interactive sprints (possibly several concurrently, resolved one focused-at-a-time in the overlay); rival/society-initiated sprints **auto-resolve deterministically** in a new tick phase (no minigame). The modal "suspend time" gate moves from `state.elopement !== null` to `hasActivePlayerElopement(state)` — non-player sprints run during normal tick advancement and do NOT suspend time. (User-selected maximal scope; the spec frames the sprint as a player overlay only, so the rival/NPC layer is a deliberate v1.5 invention.)
2. **`accumulatedAffection` goes live (Q6).** The reserved-but-dead `Scheme.accumulatedAffection` (always `0` at v1, `entities.ts:353`) becomes the per-tick Seduction accumulator; per-tick discovery probability scales with it. The one-shot completion roll is replaced by per-tick suspicion. This is the field's spec-named purpose (spec §4 L543).
3. **Abandonment = explicit dissolution-then-remarriage with a cost surface (Q25).** New `MarriageRecord.viaAbandonment` + a free `abandonMarriage` action; elopement-win abandon-on-win is opt-in per sprint (default off preserves the P9 "rep-halve only, no bigamy" behavior).

## In scope

### C1. Multi-tick Seduction-discovery suspicion (Q6 — spec §10 L774)
- **Today (one-shot):** `resolveSeduction` (`schemes.ts:515-626`) fires a single discovery roll at `endsAtTick` (`discovered = drawNext() < SEDUCTION_DISCOVERY_PROBABILITY` = 0.2, `schemes.ts:528-535`); success applies a flat affection delta; `accumulatedAffection` is never mutated (`entities.ts:353`, always `0`).
- **New (multi-tick) — net-new per-tick code path, not an edit to the completion branch.** `applySchemeResolutionPhase` (`schemes.ts:730`) today is a two-pass Chaperone-then-other reducer that `continue`s unless `scheme.endsAtTick === state.tick` (`:734`). C1 adds a parallel per-tick walk over Active Seductions ALONGSIDE the existing completion filter — pin how it composes with that branch. **Chaperone interaction (resolved — pin the mechanism):** a Chaperone landing mid-flight MUST still cancel a now-mid-flight Seduction (spec §7 L642 "cancel all in-flight Seductions targeting the same character" is not completion-gated). Today `resolveChaperone` (`schemes.ts:628`) + the pass-1 partition are completion-gated (`applySchemeResolutionPhase` `continue`s unless `endsAtTick === state.tick`, `:734`; the `:640-641` comment assumes same-tick). **Widen the Chaperone pass to scan `status === "Active" && targetCharacterId === targetId` Seductions UNCONDITIONALLY** (drop the same-tick assumption), and run that pass-1 cancellation BEFORE the new per-tick suspicion walk (so a Chaperone arriving the same tick a Seduction would roll discovery wins the race). Per tick of flight:
  - **Accrue:** `scheme.accumulatedAffection += SEDUCTION_AFFECTION_PER_TICK` (clamped at the target's headroom toward `SEDUCTION_AFFECTION_CEILING`). The flat-+80-at-completion model is replaced by incremental accrual applied to `state.affectionMap` each tick.
  - **Suspicion roll (per tick):** discovery probability scales with accumulated affection: `p = clamp(SEDUCTION_SUSPICION_BASE + scheme.accumulatedAffection × SEDUCTION_SUSPICION_SLOPE, 0, SEDUCTION_SUSPICION_CEILING)`. One draw/tick from the owner-house stream. On hit → discovery fires *mid-flight* (early), mounting an elopement sprint (C4) and flipping the scheme `Failed/Discovered` (existing `flipSchemeStatus(..., "Failed", "Discovered")`, `schemes.ts:576`).
  - **Completion (no discovery):** when `state.tick >= endsAtTick` with no discovery, flip `Completed`; the accrued affection is already applied.
  - **Temptation / perk interplay preserved:** the `TEMPTATION_DISCOUNTED_SCANDAL`(=5)/`SEDUCTION_DISCOVERY_SCANDAL`(=25) selection (`schemes.ts:553-564`) and the P15 Seduction-perk scandal-halving + affection-bonus (`schemes.ts:557-602`) carry over; the perk's affection bonus now applies per-tick-prorated or as a one-time accrual bump (default: applied to the per-tick accrual rate).
- **Determinism:** Active Seductions now consume **1 draw/tick** (was 1 draw at completion only). The new per-tick draw budget shifts the fresh-state hash; absorbed by the self-referential replay baseline (`replay-harness.test.ts` computes run-0 at runtime — no hardcoded hash to edit). `cumulativeSuccessfulSeductions` (`schemes.ts:614-624`, P15) still increments only on the non-discovered `Completed` branch.
- **Rebalance (R4):** re-tune `SEDUCTION_*` so total accrued affection over a 7-tick flight ≈ the old +80 and the integrated per-tick discovery probability ≈ the old 0.2 one-shot, unless a deliberate rebalance is intended.
- **UI:** the Schemes ledger surfaces a rising suspicion/affection bar on Active Seductions (read `accumulatedAffection`); the player can `cancelScheme` to abort before discovery. No new bus event (suspicion is read from state).
- **Constants:** `SEDUCTION_AFFECTION_PER_TICK`, `SEDUCTION_AFFECTION_CEILING`, `SEDUCTION_SUSPICION_BASE`, `SEDUCTION_SUSPICION_SLOPE`, `SEDUCTION_SUSPICION_CEILING`. The old `SEDUCTION_DISCOVERY_PROBABILITY` is retired (or repurposed as `SEDUCTION_SUSPICION_BASE`).
